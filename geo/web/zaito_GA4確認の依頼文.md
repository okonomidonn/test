## 背景
営業資料に「ChatGPT経由のユーザー68人（全体469人の14.5%）が、キーイベント95件のうち49件を発生させた（2026年9月24日〜10月21日）」と書いています。外部の評価で、次の点が指摘されました。
- キーイベントは「件数」で、同じ人の複数回を含む。人数で比べないと「成約率」は言えない
- 比べる相手に広告の流入（滞在7秒）が多く含まれ、ChatGPT経由が良く見えすぎている可能性がある
- 施策（10/8の方針転換、10/12のJobPosting、10/17のFAQ・llms.txt）とAI経由の流入の時系列を、日付で確かめていない

## 前提（テーマのコードから分かっていること）
応募は各企業の募集ページで完了するため、**zaito上では応募の完了は測れません**。zaitoで測れる行動は次のとおりです。
- `remote_apply_click`：求人ページで「応募ページへ進む」を押した（企業の募集ページへ移る直前）
- `sign_up`：メールアドレスでの無料登録
- `profile_complete`：プロフィールの入力完了
- そのほか：`fav_add`、`share`、`generate_lead`（企業向けの問い合わせ）など

まず、GA4の管理画面で**どのイベントが「キーイベント」に設定されているか**を確認してください。そのうえで、下の数字を出してください。

## 出してほしい数字
期間は2つ。
- **A**：2026-09-24〜2026-10-21（資料と同じ28日間）
- **B**：2026-10-01〜今日（最新）

### 1. 参照元ごとの人数と、行動した人の数（いちばん大事）
ディメンションは「セッションの参照元」。行は次のグループに分けてください。
- `chatgpt.com`
- `openai`（`openai / organic` など）
- そのほかのAI（`perplexity.ai`、`gemini.google.com`、`copilot.microsoft.com`、`claude.ai` などがあれば）
- 広告（`meta / paid`、`ig / paid` など）
- 広告以外の自然な流入（`(direct)`、自然検索、`ig / social` など）

| 列 | GA4の指標 |
|---|---|
| アクティブユーザー | activeUsers |
| キーイベント（件数） | keyEvents |
| キーイベントを1回以上した人の割合 | userKeyEventRate（ユーザーキーイベント率） |
| `remote_apply_click` の件数と、した人の数 | eventCount と totalUsers（イベント名で絞る） |
| `sign_up` の件数と、した人の数 | 同上 |
| 平均エンゲージメント時間 | userEngagementDuration ÷ activeUsers |

### 2. 日別の推移（期間B）
- 日付 × 「chatgpt.com と openai を合わせたAI経由」のセッション数と `remote_apply_click`
- 施策の日付（10/8、10/12、10/13、10/17）に印を付ける

### 3. AI経由の人が最初に入ったページ（期間B）
- ランディングページ × 参照元（`chatgpt.com`）のセッション数と `remote_apply_click`
- 求人ページ（`/remote/…`）、条件別（`/zaitaku/…`）、記事（`/guide/…`）、FAQ、トップ に分けて合計も出す
