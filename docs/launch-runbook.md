# AIススメル：公開と申し込み対応

更新：2026-10-26。担当：鳥居潤。現在は無料診断・見積もりの受付段階。有料契約の準備完了を意味しません。

## 毎営業日の確認

1. 運営チームのアカウントで `/ai/app/leads` を開き、未対応の申し込みを見る。
2. 無料チェックは3営業日以内に診断結果、トライアルは2営業日以内に進め方と見積もりを送る。自動返信メールは送っていない。
3. 返信したら「連絡済み」、納品・相談終了後は「完了」に更新する。
4. 通知が失敗した場合は設定・配信サービスを確認してから再送する。申込内容は保存されるので、通知メールだけを受付記録にしない。
5. 診断結果や個人情報を本人の同意なしに公開しない。削除希望はメール返信かフォームで受け付け、対象と範囲を確認して対応する。

## 専用メールの準備

- 個人用メールを公開する必要はない。独自ドメイン未取得のため、当面は公開フォームを連絡先とする。PDFにも担当者とフォームURLを記載する。
- ドメイン決定後、問い合わせ受信用メールを用意する。通知の送信元ドメインはResendで確認し、案内されるDNSレコードを設定する。実際の受信確認を行う。
- Productionだけに `RESEND_API_KEY`、`MAIL_FROM`、`LEAD_NOTIFY_EMAIL` を設定し、確認後に `LEAD_NOTIFICATIONS_ENABLED=1` を設定する。送信元・受信先は表示名なしのメールアドレス。
- 申込者向けの営業メール配信は実装していない。必要な場合は同意の取得と記録を先に整える。
- Resendの契約・DNS操作は未実施。秘密鍵はVercelの環境変数で設定し、チャットやGitに書かない。

## 有料で受ける前に確定すること

- [ ] 販売事業者の正式名称（個人事業ならその氏名）、所在地、電話番号、公開メール。
- [x] 運営責任者：鳥居潤。
- [ ] 支払方法、支払期限、追加費用、解約・キャンセル条件。契約書・見積書と `/ai/legal` の内容を一致させる。
- [ ] [見積書・依頼前確認書のひな形](agency-order-template.md) の未確定項目を埋め、正式な契約条件を確認する。作業範囲・成果を保証しないこと・変更承認・秘密保持はひな形に記載済み。
- [ ] Vercelの商用利用可能なプランへ切り替える（現在Hobby。契約・課金の変更は未実施）。
- [ ] `OPENAI_API_KEY` と `GEMINI_API_KEY`、残高・利用上限を確認し、実AIでの計測を行う（ローカル検証はmockのみ）。
- [ ] 本番にあるテスト用アカウントの一覧と用途を確認し、削除の要否を決める。本番データは自動削除しない。
- [x] Preview用DBの自動分岐を有効化。`preview/codex/dependency-security` の実在をNeonで確認。
- [x] PDF2点に担当者・問い合わせフォームURLを記載。どちらもA4・1ページで確認。

PDFの元データは `geo/web/print/*.html`。Playwrightを利用できる環境で `node geo/web/print/build_pdfs.mjs` を実行し、生成後はPDFを画像化して文字切れを確認する。個人メールは記載していない。

`npm run check:launch` は環境変数の不足を確認する補助ツールで、契約書の妥当性・配信の到達・課金プランを保証しない。

## デプロイ

1. ローカル専用DBでマイグレーション・テスト。`npm test`、`npx tsc --noEmit`、`npx eslint src`、`npm run build`。
2. PRを作成。Vercel Previewの成功とNeonの `preview/<ブランチ名>` を確認する。接続文字列をログへ出さない。
3. 新しいマイグレーションは削除・書き換えずに追加する。今回の通知・対応状況はLeadテーブルへの列追加だけ。
4. マージ後に本番デプロイ成功、公開URLの更新、PC・スマホの表示を確認する。本番では申し込みや計測の書き込みテストを行わない。
5. 新しい通知列は既存の申し込みで未通知・未対応になる。メール有効化前に既存分を整理し、対応済みは「完了」にする（自動再送対象から外れる）。

## 既存セルフ版のStripe

新規販売は終了している。既存契約がある場合だけ、テスト／本番キー、価格ID、Webhook、カスタマーポータルの整合を確認する。代行契約の料金はこのStripe月額プランと混同しない。本番へのモード変更・実課金・解約は未実施。
